# 语义识别

## 结构

聊天意图定义在 `shared/companion-intents.json`，前端 `src/domain/companionEngine.ts` 与服务端 `server/app.py` 共用同一份规则。这样本地离线回退和 FastAPI 不会出现覆盖差异。

每条规则包含：

- `id`：意图标识。
- `priority`：匹配优先级，数值越大越先匹配。
- `emotion`：六种受支持情绪之一。
- `action`：六种受支持动作之一。
- `confidence`：本地结果置信度。
- `patterns`：不区分大小写的正则表达式列表。
- `replies`：回复模板列表，按输入内容稳定选择一个。

规则按 `priority` 从高到低匹配，同优先级保持文件顺序。所有规则都未命中后，再判断一般疑问句和开放式陈述。

## 覆盖范围

当前规则覆盖 27 类意图：

1. 自伤风险的安全回应。
2. 否定式积极表达，例如“开心不起来”。
3. 难过、焦虑、孤独、压力、内耗和低落。
4. 生病、疼痛、失眠与就医提醒。
5. 分手、争吵、拒绝和关系失落。
6. 想念、拥抱、亲昵和爱意。
7. 生气、烦躁、反感与冲突。
8. 道歉。
9. 感谢。
10. 好消息、成就、庆祝和任务完成。
11. 回归、久别重逢和寻求注意。
12. 晚安、睡觉、困倦与休息。
13. 疲劳、疲惫和精力不足。
14. 开心、夸奖、笑声和积极语气。
15. 告别。
16. 身份询问。
17. 能力与使用方式询问。
18. 早安、午安、晚间问候和在线确认。
19. 饮食、饥饿、饮品和外卖。
20. 工作、加班、通勤和职业压力。
21. 学习、考试、论文、面试和作业压力。
22. 安慰、陪伴和倾听请求。
23. 无聊和消磨时间。
24. 音乐、影视、阅读、游戏、运动、旅行和宠物。
25. 天气、温度和季节变化。
26. 没听懂、没听清和请求重复。
27. 简短确认、应声和收尾语气。

规则同时包含常见英文表达、缩写、语气词和表情符号。自伤风险规则会优先于其他规则，避免被普通情绪或问候规则覆盖。

## 情绪与动作

```text
emotion: IDLE | HAPPY | SHY | SAD | SLEEPY | ANGRY
action: IDLE | JUMP | DANCE | WAVE | PUNCH | SIT
```

远程模型返回非白名单状态时，服务端会用本地规则补齐合法状态。回复文本限制为 160 字符，置信度限制在 0 到 1。

## 远程模型

服务端支持三种可选适配器：

| 提供方 | 配置 | 说明 |
|---|---|---|
| Pollinations | `LLM_PROVIDER=pollinations` | 公共接口，可能限流或排队 |
| Gemini | `LLM_PROVIDER=gemini` | 需要服务端 `GEMINI_API_KEY` |
| OpenAI 兼容接口 | `LLM_PROVIDER=openai-compatible` | 可接 Groq、OpenRouter、Ollama、LM Studio 等 |

远程调用失败、超时、限流、返回非 JSON 或非法状态时，服务端自动调用本地规则。

## 扩展方式

1. 在 `shared/companion-intents.json` 添加或调整规则。
2. 为 `patterns` 使用前后端都支持的正则语法。
3. 为 `replies` 提供至少一个简洁回复。
4. 在 `src/domain/companionEngine.test.ts` 和 `server/test_app.py` 增加相同案例。
5. 执行 `npm run test`、`npm run test:api`、`npm run typecheck` 和 `npm run lint`。

新增规则时要重点检查重叠场景，例如“我想死你了”是亲昵表达，不应命中自伤风险规则。
